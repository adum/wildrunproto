# Wild Run Prototype Architecture (Short)

## Entry Points
- `examples/prototype.html` loads the sandbox UI for manually toggling hints, challenges, and passives.
- `examples/play.html` loads the "play" flow with the map, shop, treasure, and progression loop.
- `examples/map.html` is a standalone map generator and simulator.

## Core Runtime
- `examples/prototype/context.js` defines shared state, element refs, utility helpers, and the central `app` object that modules attach to.
- `examples/prototype/board.js` wraps the GhostBan board (from `build/index.min.js`), drives SGF loading, move evaluation, and creates overlay canvases.
- `examples/prototype/main.js` wires DOM events to module actions and kicks off the initial SGF load.
- `examples/prototype/config.js` merges defaults with `examples/prototype/config.json` at runtime and applies level bounds to sliders.

## Gameplay Modules (Prototype + Play)
- Hints: `examples/prototype/hints.js` manages hint selection and the markup overlays.
- Challenges: `examples/prototype/challenges.js` toggles challenge states and resets them.
- Timers: `examples/prototype/timers.js` runs mystery/enigma/speed timers and their UI.
- Passives: `examples/prototype/passives.js` handles time-extend, second-chance, free-upgrades, big-money, shopaholic, and capture indicators.
- Overlays & FX:
  - `examples/prototype/overlays.js` draws gray stones, enigma rings, infection rings, and hint bands.
  - `examples/prototype/ghost.js`, `examples/prototype/fire.js`, `examples/prototype/frost.js`, `examples/prototype/flip.js`, `examples/prototype/spotlight.js` render animated challenges.
  - `examples/prototype/effects.js` handles particle/shatter FX.
- Styling for both prototype + play is mostly in `examples/prototype.css`; map-specific styles live in `examples/map.css`.

## Play Mode Flow
- `examples/play/main.js` orchestrates run state, coins, hints/passives, boss challenges, overlays, and the map loop.
- `examples/play/map-ui.js` renders the hex map and handles interactions.
- Problem data is loaded from `gp/problems.js` (generated by the GP tools).
- Play uses the same underlying modules as the prototype (imported directly from `examples/prototype/`).

## Map Generator
- `examples/map.js` is the standalone hex-map generator for tuning weights and rules.
- `examples/img/` stores map node icons.

## Adding New Features
- New hint: add logic in `examples/prototype/hints.js`, wire UI in `examples/prototype.html`, add styles to `examples/prototype.css`, and register in `examples/play/main.js` `HINT_DEFS` if it should be used in play mode.
- New challenge: add a module (or extend `examples/prototype/challenges.js`), create any overlay canvas in `examples/prototype/board.js`, hook UI in `examples/prototype.html`, add config defaults in `examples/prototype/config.json`, and register in `examples/play/main.js` `CHALLENGE_DEFS` + `challengePool`/`challengeCombos`.
- New passive: add logic in `examples/prototype/passives.js`, update UI in `examples/prototype.html`, add config defaults in `examples/prototype/config.json`, and register in `examples/play/main.js` `PASSIVE_DEFS` + `passivePool`.
- Config-only tuning: change values in `examples/prototype/config.json` (the JS file applies them at runtime).

## Testing & Usage
- Serve the repo and open in a browser:
  - `python -m http.server`
  - Open `examples/prototype.html` for manual feature testing.
  - Open `examples/play.html` for the full run flow.
  - Open `examples/map.html` for map generation only.
- Prototype events log to the on-page event log; play events log to the browser console. Make sure interactions still update the board and overlays as expected.
